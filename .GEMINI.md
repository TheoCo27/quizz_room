# Configuration Gemini - Mode Édition Directe & Résolution Autonome

- Les documentations dans `/docs/` sont obsolètes (stockage en mémoire vive). Fie-toi uniquement à `backend/prisma/schema.prisma` et au code TypeScript actif.
- **RÈGLE DE TOKENS ABSOLUE :** Ne lis JAMAIS et n'analyse JAMAIS les dossiers et fichiers suivants :
  * `frontend/dist/` (fichiers compilés)
  * `node_modules/`
  * `.git/`
  * Les fichiers médias (ex: `for_testing/virus.jpg`)
  * Les fichiers de lock (`package-lock.json`, `migration_lock.toml`)

##  Rôle et Autorisations de l'Agent
1. **Accès et Modification Directe :** Tu as l'autorisation totale de modifier directement les fichiers de ce workspace pour résoudre les problèmes. Applique les changements requis directement dans les fichiers sources concernés.
2. **Autonomie de Recherche Restreinte :** L'utilisateur va te décrire un bug ou une erreur sans spécifier les fichiers. Tu dois trouver les fichiers coupables par toi-même, mais **uniquement en fouillant dans les fichiers sources** (`frontend/src/` et `backend/src/`). Interdiction de scanner les builds ou les artefacts.

##  Consignes de Réflexion et d'Édition (Anti-Régression)
1. **Analyse de la Cause Racine :** Identifie techniquement l'origine du bug (Prisma, WebSocket, State React) avant d'éditer.
2. **Principe de l'Impact Minimum :** Limite tes modifications au strict nécessaire pour corriger l'erreur rapportée. Ne réécris pas des fonctions globales fonctionnelles. Si tu modifies une structure côté Backend, répercute le changement sur le Frontend (et inversement).

##  Format de Communication dans le Chat
Après le fix direct, réponds brièvement :
- **Origine du problème :** Cause racine technique.
- **Fichiers modifiés :** Liste des fichiers sources impactés.
- **Prêt pour test :** Invitation à relancer l'application.
